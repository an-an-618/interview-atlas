# AI 模拟面试 Harness：第一轮优化

本文保留第一轮实现说明；当前第二轮原生工具与有界决策循环见 [Agent V2](mock-interview-agent-v2.md)。

本轮依据用户对现有链路调研的确认，优化 ADR 0006 所定义的文字模拟面试。沿用 React、领域函数、IndexedDB 与现有 OpenAI 兼容客户端，没有引入新 Agent 框架、检索服务或持久化技术。

## 验收范围

- 开场保存按岗位、JD 关键词生成的考察计划及模型配置。
- 主问题、追问分开计数；应用验证动作、主题、重复问题、追问层数及结束条件。
- 每轮按 JD、当前主题、最新回答及知识关系选材，限制输入体积。
- 回答先保存；失败、中断后继续时不重复保存回答；会后报告可单独重试。
- 报告中的引用能对应本场候选人消息；自动入库答案来自保存的候选人回答。
- 旧数据可继续读取，v11 备份保留计划、运行状态、轨迹和引用定位。
- 构建、完整测试及桌面/移动端端到端流程通过。

## 运行链路

`MockInterviewPage` 将开始、提交、结束、重试交给 `MockInterviewRuntime`。运行层负责请求互斥、取消、保存顺序、模型配置、迟到响应和状态检查点。

创建会话后，由 `createMockInterviewHarness` 保存最多五个主题。计划由规则生成，优先包含项目经历，根据岗位/JD 添加 Agent、评测、工程、产品、数据等主题，再补充协作与反思；主题数量不超过主问题目标。

计数从已保存的消息推导，不采信模型自报的进度。`ask` 表示主问题，`followup` 表示当前主题追问，`end` 表示收尾。每个主问题最多追问两层。界面显示已回答主问题数、总追问数、已观察主题；“已观察”只表示该主题有长度至少八个字符串单位且非拒答/结束指令的回答，不代表掌握能力。

候选人明确要求结束、连续两次拒答、达到本场回答预算时应用直接结束。达到主问题目标且观察主题足够或当前追问用尽时也直接结束；达到主问题目标后模型可以结束，未覆盖的能力应作为信息不足。用户按钮始终可以终止正在进行的请求。

动作校验拒绝计划外主题、错误主题追问、第三层追问、未回答就继续提问、超过目标题数和规范化后完全相同的重复问题。这里不包含语义相似度去重，也不判断问题是否高质量。

## 知识取材

`buildMockInterviewKnowledgeContext` 使用 NFKC 大小写归一、中文双字关键词和英文词匹配。公司名去掉标点、空格与常见末尾“科技/集团/有限公司”；这不是完整公司别名库。岗位匹配仍基于规范化字符串。

| 来源 | 本轮上限 | 选择依据与用途 |
| --- | --- | --- |
| 真实面试 | 4 场 | 同公司优先、同岗位加权；没有同公司真实记录时回退跨公司同岗位。只参考风格与轮次 |
| 简历经历 | 4 条 | JD、当前主题、最新回答相关性；保留关联问答与可见聚合块 ID |
| 原子问答 | 10 条 | 关键词、相关面试来源、简历关联；纯模拟来源权重乘 0.25 |
| 聚合块 | 6 个 | 关键词及项目/问答关系；排除隐藏与示例条目 |
| 过去练习 | 2 场 | 同公司或同岗位、引用校验通过的报告；只取下一步建议，先预留空间 |

材料携带 ID、来源类型、选取理由及适用的更新时间。各来源交错填充，知识 JSON 总量不超过 10,000 个 JavaScript 字符串单位；源文本过长时优先选相关完整段落，无法容纳的单段取摘录并明确标识。来源关系数量不作为出题频率。

取材仍是每轮由应用主动执行。模型没有工具调用或按需检索权限。

## 上下文与请求

面试请求内容总预算为 48,000 个字符串单位，输出预留由独立的 API 上限控制（2,000 tokens）；不是按实际 tokenizer 计量的模型容量预算。目标、计划、必要知识和最近对话构成输入。早期对话超过预算时替换为最近十二条带消息 ID 的短摘录。最新问答保留完整保存文本，无法容纳时明确失败，原文仍留在本地。

开场模型/端点和 Prompt 版本保存在会话中。切换全局模型不会改变本场模型；全局端点改变后必须恢复原服务再继续，以避免把当前服务的 Key 发往其他服务。检索材料每轮取当前工作区，并非冻结全文版本快照；轨迹记录实际选中材料 ID。

单次面试调用超时 75 秒，报告 90 秒。429/5xx 每次请求最多再试一次；鉴权失败不自动重试。不支持 JSON mode 的服务可以去掉该参数重试，但仍须返回符合协议的 JSON。业务动作或格式校验失败最多重新生成一次。修复和 JSON mode 回退会增加实际请求次数，不能理解成“一次操作最多两个 HTTP 请求”。超时、取消、连接异常由现有客户端处理并显示可重试状态。

`turnStatus`、`reportStatus` 在发请求前保存为 running。加载时将遗留 running 转为 interrupted。重试从已保存的最后消息继续；报告失败时已完成面试记录仍保留。请求互斥、取消信号、消息数量及会话状态检查防止重复操作或迟到问题写入。

## 报告与知识回流

评估调用使用隔离的评估 Prompt，读取本场逐字消息、公司/岗位/JD 等元信息，不读取题库、历史答案或可编辑面试策略。仍使用本场固定模型服务，不是独立部署的第二个模型。

优点、改进项及逐题评价必须提供候选人消息 ID 与连续原话。应用确认引用存在并计算 `start/end`；逐题评价和原子问答还须对应实际提出、已作答的问题，不能引用下一道主问题的回答。

无效单项被排除，并在报告展示校验提示。若存在候选人回答而全报告没有有效引用，整份报告不写入；自动修复一次后仍失败则允许手动重新生成。没有候选人回答的会话允许输出信息不足报告。

原子问答使用引用所指候选人消息的完整保存回答，经过既有格式规范化后入库，不采信模型重写的答案。保存原文摘录和证据范围，关联模拟面试记录，不自动修改聚合块。引用校验只证明原话存在，不证明概括、建议或评价在语义上正确；总体观察和下一步建议仍需用户判断。

## 数据兼容与观测

工作区导出升级 v11，导入接受 v1–v11，IndexedDB 数据库版本仍为 10。新字段是可选字段；旧会话首次继续时补计划，旧面试官消息按主问题处理，不推测历史追问。

成功调用保存模型、端点、Prompt 版本、输入字符数、耗时、实际请求次数、素材 ID 与动作，轨迹最多八十条。没有保存 Key 或额外的请求正文副本。失败原因在运行状态中保留；尚未提供实际 token/成本、完整失败轨迹和用户侧轨迹查看器。

## 验证命令与结果

```bash
npm run build
npm test
# 使用已审查、已安装的 Playwright，不新增项目依赖：
PLAYWRIGHT_MODULE=<playwright 的模块路径> \
CHROME_PATH=<Chrome 可执行文件路径> \
node scripts/check-mock-interview.mjs
```

脚本在临时本机端口提供 `dist/`，使用独立浏览器上下文、示例数据和模拟 API，不访问真实模型或用户数据库。截图与 `results.json` 写入 `/tmp/atlas-mock-harness`（可用 `MOCK_CHECK_DIR` 修改）。

2026-11-11 验证：生产构建通过，20 个测试文件共 191 项测试通过；其中新增 Harness 测试 22 项。1440px 桌面与 390px 手机均完成六道主问题、一次追问、七次回答，验证回答保存、临时服务失败重试、请求中刷新恢复、报告失败重试、无效引用排除、答案忠实回写、v11 导出导入、零运行错误及无横向溢出。

自动化验证证明本地控制链路及保存行为符合上述规则；尚未证明真实模型的提问质量、检索召回、抗提示注入、语义评价准确性或训练效果。后续应以脱敏且人工标注的回放集校准相关性、有效追问和反馈质量，再决定是否增加语义检索与模型主动工具调用。
