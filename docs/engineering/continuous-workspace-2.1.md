# 2.1 连续整理工作台（本地版本）

本次主线是把面经中的真实材料整理为下一次能用的回答。一级入口为首页、整理、知识库、练习；复用 v11 工作区及已有导入、提取、录音、分享、关系与面试运行逻辑。本次用户明确要求纯本地，未创建 GitHub issue、PR 或远端发布。

## 使用路径

1. **首页 → 整理。** 导入先保存原文。队列显示提取状态，也可手动添加问答；核对候选后采纳或忽略，再单独确认或忽略聚合块关联。采纳并继续后，未决定的关联仍在目录提示。首页恢复同一份面经及上次候选。
2. **知识库 → 对照编辑。** 四类对象共享列表与详情；原有分类管理、简历解析仍在列表底部入口。编辑回答时展开来源问答和真实经历，可以继续查看原始面经再返回。正文与关系各自保存，离开未保存的对象时选择保存、放弃或继续编辑。
3. **练习 → 模拟 → 历史复盘。** 首页和闪卡复习共用卡组、卡片和翻面状态。面试配置跨设置返回保留；回答先写入再生成下一问，失败针对已保存回答重试。报告失败时逐字稿仍可阅读，引用定位本场原话，并可打开已有本场问答、关联聚合块或查找相关知识。

全局搜索返回保留查询词、分类及列表位置。窄屏整理优先候选，通过“查看依据”读原文；知识库从列表进入详情，通过抽屉对照；复盘点击引用切到逐字稿，再返回同一条反馈。收藏、分享、设置、完整备份与恢复继续使用原有功能。

## 保存边界

业务数据仍保存在既有 repository 中，未修改备份格式。审核决策、问答创建、正文与关系保存通过队列写入，成功后更新界面；失败保留当前内容并提供原处重试。问答来源包括原始面试 ID 和可匹配的原文片段，关联不复制或覆盖正文。

新增界面状态使用 `atlas-2.1:` 前缀保存在 sessionStorage，包括入口、候选位置、筛选、列表位置、编辑草稿、面试配置与共享闪卡状态。刷新和同一窗口内切换可恢复；关闭整个浏览器会话后，这些界面选择可能重置，已保存的业务数据不受影响。
