# AI 面试 Agent：本地工具与有界决策循环

第二轮升级依据用户提供的流程图完成，沿用唯一面试官、现有 OpenAI 兼容 API、领域状态与 IndexedDB。没有引入 Agent SDK、云端知识服务或新的依赖。第一轮的应用选材成为原生工具不被支持时的兼容路径。

## 本轮行为

面试官可原生调用 `search_knowledge`、`read_material`、`get_related_materials`、`get_interview_state`。工具调用消息和 tool 结果按实际 `tool_call_id` 返回模型，模型据此改检索、读细节、追问、切换主题或结束。最终问句仍经过原有动作校验，报告流程保持独立。

原生模式不预先塞入整组知识。它注入目标、JD、计划、当前消息索引、最近对话和已核验报告中的练习建议，按需取材。旧历史超过预算时继续使用带 ID 的摘录；最近完整回答无法容纳时失败并保留原文。

| 工具 | 合法输入 | 结果 |
| --- | --- | --- |
| search_knowledge | query、reason；可选 kind/company/role/limit | 最多六条材料，ID、短摘录、来源、关键词命中和权重 |
| read_material | 本轮已发现的 materialId、reason；可选 start/length | 最多 2400 字符原文、范围与总长度；局部读取为 incomplete |
| get_related_materials | 本轮已发现的 materialId、reason；可选 limit | 最多六条已有关系中的可见邻接材料 |
| get_interview_state | reason | 已问/已答、当前主题、追问层数、剩余预算、证据观察、允许动作 |

工具使用当前工作区的本轮快照，不访问磁盘或外网，不修改知识。隐藏聚合块和示例数据不进入目录；模拟面试全文不作为真实面试参考。模拟来源的原子问答仍可用于准备，检索权重为 0.25，并明确不是本场证据。

关系从已有 ID 构建，支持双向读取。每轮必须先检索得到材料 ID，再读取原文或邻接材料；不能凭空给 ID 读取其他条目。检索以中文双字词与英文词为基础，并按来源权重排序；公司与岗位条件约束材料自身元数据，不是全量语义检索。

`ok`、`no_results`、`incomplete`、`error` 是不同状态。找不到材料不说明事实不存在，局部原文不代表完整材料，参数错误不允许模型绕开限制。工具结果超过 4000 个字符串单位时再次压缩并标记 incomplete。

## 预算与适配

每轮最多三次工具调用、五次实际 HTTP 模型请求、120 秒。无效工具和重复工具请求同样计入三次预算；同参数调用归一化去重，reason 不影响重复判定。模型单次最多返回八个调用，超出的协议直接失败；合法批次超过剩余额度的调用收到预算错误而不执行。

三次工具预算用完后停止声明工具，明确要求生成最终动作。第五次请求预留给最终动作；业务 JSON 或动作不合法最多修复一次。剩余不足十五秒时停止检索、要求最终问题；服务超时或不遵守协议时显示可重试失败，禁止把原始返回当作问句。429/5xx 最多再请求一次，所有实际请求包括兼容回退和修复都共享五次上限。

48,000 字符预算计入工具声明、消息、工具调用及返回结果；这是 JavaScript 字符串计量，不能直接等同 token 数或真实费用。单次原生输出上限 2400 tokens，单次面试请求最多 75 秒，轮级取消覆盖兼容路径。报告有独立的 90 秒单次限时及原有修复策略。

HTTP 400/404/422 返回明确的 unsupported/unknown tools 等信息时，才回退第一轮应用选材；鉴权、网络、临时服务错误不能当作工具不支持。会话保存 fallback 原因，随后该场继续兼容路径，界面显示“应用预选材料”。新建面试重新探测。

第一次返回纯文本 JSON 只能标记 unconfirmed，不能据此宣称支持工具。实际返回原生 tool_calls 后标记 native，并在同场后续无需工具的轮次保留确认状态。服务没有声明工具时继续返回 tool_calls 会被拒绝执行并在预算内失败，不无限循环。

## 证据与状态

计数从消息推导，已问、已答和证据充分分别维护。拒答仍算已答，不视为有效能力观察。

模型可以返回 `observation`：被回答主题、缺口、下一步关注点、证据是否充分、证据引用。应用只接受当前主题、最新候选人消息 ID 和该消息的连续原话，计算保存文本的 start/end。不能引用历史题库、面试官消息、其他主题或旧回答。引用无效时整个最终动作需要修复，不能默默把虚假证据写入。

有缺口时不能标记充分；充分至少有一条真实引用。引用验证证明原话存在和对应本场，不证明模型对“充分”的语义判断正确，更不表示候选人掌握能力。缺失 observation 时保留已有记录，不凭空补充分性。

每个主题保存最新一次已校验观察，逐轮记录中的 gaps/nextFocus 保留历史推进过程。本场证据和历史练习建议分开；取材记录和内部缺口在面试结束后可展开查看，进行中不展示内部追问策略。

## 保存、恢复与数据兼容

`MockInterviewRuntime` 在保存候选人回答后请求下一轮。Agent 每次工具批次、回退和最终成功/失败/中断均通过异步 onTrace 写入同一轨迹 ID；最终写问题时合并轨迹，避免同轮重复记录。轨迹保存模型、端点、输入字符峰值、请求次数、耗时、模式、工具名称/选择理由/参数摘要/来源 ID/结果、最终动作及预算原因，不额外保存 Key 或完整请求正文。

状态仍由运行层统一互斥和取消，写轨迹时校验会话 active 与消息数量，写问题前再次拒绝过期响应。失败与刷新后继续，不重复保存已存在的回答；报告可以单独重试。加载遗留 running 时转 interrupted，保留轨迹。工具目录不是完整版本快照，源材料之后可改；轨迹是可追溯索引，不是不可变审计日志。

结构保留 harness version 1、工作区备份 v11、数据库版本 10，新增 mode、observations 与工具轨迹为可选字段。当前应用可以读旧备份并往返新字段；旧版应用不保证理解新字段。导入时核验枚举、数量、非负整数以及证据原文与被回答主题。每场最多保存八十条运行轨迹。

报告仍由隔离评估 Prompt 读取本场完整逐字稿，不读取工具结果、旧答案或内部观察。报告引用单独校验，原子问答复制已保存的真实回答。

## 验证

```bash
npm run build
npm test
PLAYWRIGHT_MODULE=<已有 Playwright 模块路径> \
CHROME_PATH=<本机 Chrome 路径> \
MOCK_CHECK_DIR=/tmp/atlas-mock-agent-v2 \
node scripts/check-mock-interview.mjs
```

测试覆盖原生消息与 ID 回传、读取与关系链、参数/范围/可见性、三类非成功结果、重复/过量/不配合调用、预算、取消、能力探测、明确回退、当前原话校验与备份保真。交互脚本用隔离浏览器和同组模拟回答，对照桌面 1440px、手机 390px 的 native/fallback 四条完整路径，验证问题、追问、保存、失败重试、刷新恢复、独立报告、取材记录及导出导入。

模拟 API 用固定策略返回工具请求和追问，用于验证协议与应用行为；不能据此声称检索准确率或面试质量提高。真实模型回放评测仍需脱敏且人工标注的数据集，关注相关性、无效检索、重复问题、有效缺口追问、候选人证据污染、时延与实际 token 费用。

2026-11-11 最终验证：构建通过；21 个测试文件共 208 项测试通过，其中新工具循环测试 17 项。native/fallback × 1440/390 四条路径均完成六道主问题、一次追问、七次回答，保存、服务错误重试、请求中刷新恢复、报告重试、取材记录、v11 备份往返均通过，无运行错误和横向溢出。额外回归验证了 React 选项晚于持久化写入时，失败轨迹不被覆盖、即时回退检查点不会误写为 idle。

同组模拟回放中，每条 native 路径的已完成轮次调用工具 21 次、请求模型 28 次；fallback 为 0 次工具、8 次模型请求（含首次不支持工具的探测）。四条路径连同人为失败、刷新中断和报告总共收到 96 个 HTTP 请求。结果和截图在 `/tmp/atlas-mock-agent-v2`；这些计数用于核对循环开销，不代表真实模型费用或质量。
