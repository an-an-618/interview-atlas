# 全文面经提取：Harness 与提示词

关联 [Issue #18](https://github.com/an-an-618/interview-atlas/issues/18)。适用范围为导入面经与重新拆解；模拟面试主持和模拟面试反馈协议保持原有行为。

## 目标与验收

- 全文用于问题识别与遗漏复查；回答阶段按问题锚点提供局部原文上下文。
- 按阶段提供规则和数据：问题清单、遗漏复查、回答整理、同步块匹配。
- 识别口语追问、祈使式提问、转写缺少问号或说话人标签的提问；一个独立回答目标对应一个候选。不设期望题数，不补写不存在的问题或答案。
- 清单分页必须显式结束；复查发现的新问题进入同一清单。每个问题有可定位的原文证据。
- 分批整理回答，校验每个目标 ID 恰好返回一次；截断、缺失、重复和错误 ID 不得静默变成成功。
- 同步块按需检索，匹配不得改写、合并或删除候选。
- 沿用后台队列的 Promise、AbortSignal 和进度回调；只有完整结果返回后才进入人工审核。
- 自动测试覆盖全文识别、局部回答上下文、超过 40 题、遗漏补充、长回答、输出截断、取消、最终返回及异步队列兼容。模拟测试不等价于真实模型召回率验证。

## 实现说明

入口保持 `AIClient.extractInterview(config, apiKey, input, signal, onProgress)`，返回 `Promise<AIExtractionCandidate[]>`。应用级异步队列继续负责运行、存储和完成通知；本模块不操作数据库或弹窗。

规则放在 system，当前阶段的证据放在 user 的 JSON 中。按阶段选择提示词常量，具有类似 Skill 的按需加载效果，使用确定性代码编排；没有引入 Agent 框架、外部 Skill、工具执行权限或模型自行规划循环。

| 阶段 | 输入资料 | 输出与校验 |
| --- | --- | --- |
| 问题清单 | 全文、公司/岗位/轮次、已识别问题 | 每页至多 24 题，标题、提问原句、原文位置、`hasMore`；原句必须可定位 |
| 遗漏复查 | 全文、已有问题 | 专查追问、并列问题、后半场和无回答问题；新增项补入清单 |
| 回答整理 | 当前最多 4 个问题及各自从本题到下一题前的原文上下文 | 每个 ID 恰好返回一次；以面试者第一人称整理 `answerPoints` 和标签 |
| 同步块匹配 | 问题、答案预览、本地检索出的每题最多 6 个同步块 | 必须使用该题的候选 ID 或 null，不允许修改问答正文 |

全文按最多 1,200 个 UTF-16 code units 标注证据编号，保留每个原始字符和换行。问题识别与遗漏复查会发送全部编号片段，不逐段独立识别。问题引用优先逐字定位；跨片段以及仅有 Unicode、空白、标点差异的引用会回映到原文。仍无法定位时，只有指定片段与问题存在词面交集才使用该片段中的受限原文窗口，否则拒绝候选。

清单达到单页数量时会继续检查下一页，即使模型误报结束。再次声明还有问题却没有新增条目时失败，避免无限循环。遗漏复查也支持分页。模型自己漏掉的问题仍可能未被发现，不能把这套机制称为“保证全文召回”。

回答阶段根据问题在全文中的锚点构造局部上下文，范围从本题前少量文字延续到下一问题之前，避免每四题重复发送整篇原文。最多两个回答批次并发；批次发生截断或 ID/字段错误时缩小到最少单题，已经完成的批次不重复调用。回答必须保持面试者第一人称或直接陈述口吻，并对“候选人表示：”等明确转述前缀做确定性清理。

模型按内容结构返回 `answerPoints` 数组。每一点承载一个完整回答角度，相关事实、解释和例子留在同一点，角度变化时另起一点；禁止按单句机械拆分或在文本中添加序号、圆点和小标题。数组在入库时规范化为“一点一行”的纯文本，以兼容原有搜索、导出和编辑能力。单点回答按普通段落展示，多点回答由 UI 绘制节点与连接线。数据库和备份格式 v8 会将旧原子问答长段落按原有句子边界重新排版；v9 将同一规范扩展到同步块正文。两次迁移都只插入换行，不调用 AI、不增删或改写用户文本。

同步块本地检索使用中文双字词和英文词的重合度，标题优先；范围覆盖所有未隐藏同步块，不再只取前 50 个。每题取前 6 个有词面重合的选项，提供最多 1,200 字正文预览。最多两个匹配批次并发；匹配是可选增强，持续失败时保留已完成问答并放弃该批建议。此实现无需 embedding 服务，但会漏掉完全不同措辞的同义匹配；用户仍可手动关联。无候选时跳过模型匹配。

审核数据从 v10 起分别保存 `questionDecision` 与 `syncDecision`。采纳问答只创建原子问答；采纳关联只建立到已有同步块的关系边，并要求 `createdQuestionId` 已存在。忽略关联可以独立执行且不影响问答入库；忽略问答会同时关闭尚未处理的关联建议。旧版 `decision` 与 `connectToSuggested` 在升级时迁移为对应的双决策状态。

## 资源和状态边界

- 单请求 180 秒；任务在请求之间检查 45 分钟总时限，并拒绝超时后到达的响应。最多 240 次 completion 尝试，JSON 模式兼容降级可能增加 HTTP 请求。
- 提取请求默认输出预算为 16,000 tokens。长度截断会直接缩小当前页或批次，格式错误最多原样重试一次；不会提交半截 JSON。
- 输入上限 100,000 UTF-16 code units；问题清单超过 400 题明确失败。容量限制不等于固定期望题数，也没有通过凑题达到数量指标。
- 全文超出 Provider 容量时提示换长上下文模型，不自动丢掉后半篇。
- `progress.phase` 保留旧接口，新增可选 `stage` 为 `inventory | coverage | answers | matching`；计数是已完成/预计工作单元，分页或缩小输出批次会调整总量。
- 全文仅在问题识别与遗漏复查阶段重复发送；回答阶段发送按问题锚点裁出的局部上下文。Provider 支持重复前缀缓存时可进一步降低固定上下文成本。
- 后台生命周期由 Issue #15 队列管理：关闭弹窗或切换页面继续；刷新、关闭应用会中断。只有全流程成功才写入待审核清单并通知。

## 验证

`src/ai/interviewExtraction.test.ts` 用确定性模拟响应验证：

- 53 题多页清单、复查补回最后一题、原文顺序、长回答不被 12,000 字限制截断。
- 全文在问题识别与复查请求中保持完整；答案整理仅接收按问题位置确定的局部上下文。
- 原文引用、重复出现的问题、无答案问题、缺少/重复/未知 ID、停滞分页、截断恢复及资源边界。
- 检索第 65 个同步块、排除隐藏项、按阶段隔离数据、取消与超时。

`src/ai/openAICompatibleClient.test.ts` 验证实际请求封装、JSON 模式、参数、重试、鉴权和拒绝行为。既有后台队列与领域测试继续覆盖完成后入库、取消和晚到结果。

`scripts/check-background-extraction.mjs` 的模拟 Provider 已适配多阶段协议，可验证关闭弹窗后继续、排队、通知、PC/H5 采纳和刷新中断。

以上测试证明控制流和校验行为，不证明真实模型的提取质量。真实质量验收需要在用户主动提供/运行的样本上，人工标记提问清单和关键回答事实，固定模型比较旧版与新版的：

- 提问召回率：人工标注问题中被正确识别的比例。
- 提问准确率：生成候选中确实对应原文提问的比例。
- 回答事实覆盖率和错配率，重点检查跨话轮补充、否定、数字与长回答。
- 无来源新增事实、每场请求数、输入/输出 tokens、费用和失败率。

建议至少覆盖：规范 Q/A、无说话人标签转写、超过 40 题、多次省略追问、长回答跨编号边界，以及只有寒暄的负例。逐题匹配与原文核验优先，不能只看候选数量上升。
