# ADR 0006: AI mock interview lifecycle

- Status: Accepted
- Date: 2026-10-01
- Owners: repository maintainers

## Context

模拟面试需要连续调用用户配置的模型，结合岗位信息与个人知识库追问，并在结束后生成反馈和可追溯的原子问答。会话可能由模型主动结束，也可能由用户提前结束；模型分析失败不能导致整场逐字稿丢失。

该流程扩展了 ADR 0003 的 AI 边界。普通面经拆解仍由用户逐项审核，模拟面试则是用户明确启动的一次自动入库工作流。

## Decision

在现有 `AIClient` 边界中增加两个领域级操作：

- `continueMockInterview` 使用面试官 Prompt 生成下一轮问题和结构化结束信号；
- `generateMockInterviewReport` 使用独立评估 Prompt 生成反馈报告和原子问答。

公司、岗位、目标轮次、JD、补充信息和知识库上下文由应用固定注入。用户只能编辑面试官策略区，不能移除输出协议和安全约束。

知识库上下文按相关性和数量截断：

- 最多 6 场同公司历史面试，同公司同岗位优先；
- 最多 36 条原子问答；
- 最多 24 个同步块；
- 最多 16 条简历经历。

每条用户回答先写入 IndexedDB，再请求模型。结束时先创建带 `simulated` 标识的面试记录并保存完整逐字稿，然后异步生成反馈和原子问答。分析失败时保留面试记录并允许重试。

自动生成的原子问答引用该面试记录，但不带额外“模拟面”标识，也不自动连接同步块。只有面试记录负责表达来源类型。

## Alternatives considered

### 报告生成成功后再保存

拒绝。网络、额度或结构化输出错误会导致用户已经完成的对话无法进入知识库。

### 每轮发送完整工作区

拒绝。与数据最小化原则冲突，也会快速增加上下文成本并稀释相关信息。

### 复用面试官 Prompt 生成反馈

拒绝。面试官在过程中不得评价答案；独立评估 Prompt 可以降低角色混淆，并对报告使用不同的输出结构和证据要求。

### 原子问答再次进入逐项审核

暂不采用。用户已经明确启动模拟并完成回答，自动回流是该功能的核心价值。结果仍可在知识库中编辑，且不自动建立同步块关系。

## Consequences

- 进行中的模拟面试可跨刷新恢复。
- 用户主动结束和模型主动结束使用相同的持久化与报告链路。
- 模拟面试会发送比单篇面经拆解更多的个人上下文，界面必须在开始前显示发送类别、数量上限和目标端点。
- 模型可能错误模仿历史风格或生成不准确评价；报告必须引用逐字稿证据，原始对话始终保留。
- 工作区导出格式升级为版本 5，IndexedDB 升级为版本 6，并新增 `mockInterviews` store。

## Validation

- 每次用户回答在模型请求前持久化。
- 用户结束后，即使报告请求失败，面试记录与逐字稿仍存在。
- 模型返回结束信号时自动进入同一结束流程。
- 同公司同岗位记录在 Prompt 上下文中优先于同公司其他岗位。
- 报告解析拒绝缺少有效内容的响应，并限制字段和标签数量。
- 自动生成的原子问答可追溯到模拟面试记录，且不自动连接同步块。
- JSON 导出与恢复完整保留模拟会话、报告和关系。
