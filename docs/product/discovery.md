# 产品需求探索

状态：探索中

更新时间：2026-06-19

> 本文保留早期探索结论。当前产品基线见 [产品上下文](product-context.md)，一期可评审需求见 [一期 PRD](prd-v1.md)。

## 产品目标

帮助求职者把分散的面试经验、个人回答思路和简历经历整理成一个本地运行、可以持续编辑和复习的个人面试知识库。

## 当前问题判断

面试信息通常散落在聊天记录、文档、录屏转写和他人面经中。用户需要反复整理相似问题，却缺少能够识别重复内容、保留个人回答并追溯原始面试记录的工具。

## 待验证的核心对象

- 面试记录：一次具体面试及其来源信息
- 原子问答块：问题、答案和相关材料组成的最小可编辑单元
- 同步块：多个问答块共享或引用的稳定知识内容
- 简历经历：基本信息、实习经历和项目经历
- 分类与索引：用户自定义的文件夹、标签或关联方式

这些名称只是讨论语言，尚未形成最终数据模型。

## 候选一期能力

1. 粘贴面经原文并保存来源。
2. 通过可选 AI 服务提取问题、答案和相关材料。
3. 用户审核、修改和确认提取结果。
4. 编辑原子问答块，并把它们组织成一次面试记录。
5. 人工创建同步块，并将多个相关问答块连接到同步块。
6. AI 只提供同步候选建议，不自动合并或覆盖用户内容。
7. 首页展示需要复习的高频同步块，并能回到相关原始记录。

## 暂不进入一期

- 录屏、视频管理和实时转写
- 多人协作和云同步
- 招聘企业端功能
- 自动投递或求职流程管理
- 未经用户确认的自动合并和批量改写

## 必须在 PRD 中回答的问题

- 一期核心用户是谁，最频繁的使用场景是什么？
- 面经导入失败或信息不完整时，用户如何纠正？
- 同步块保存共享正文、引用关系，还是两者结合？
- 问答块更新后，哪些内容应同步，哪些内容必须保持独立？
- 高频如何计算，用户能否手动置顶、隐藏或调整？
- API Key 如何保存，支持哪些模型协议，失败时如何降级？
- 简历和面试内容如何导出、备份和彻底删除？
- 本地 Web 应用与桌面应用各自带来什么安装和安全成本？
