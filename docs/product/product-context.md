# 千面产品上下文

- 状态：Active baseline
- 更新时间：2026-09-30
- 适用范围：产品、设计、工程、测试与 AI 协作
- 依据：仓库 README、`docs/product/discovery.md`、PC v3 原型、H5 v5 原型

## 1. 一句话定义

千面（Interview Atlas）是一个本地优先、AI 辅助但由用户最终决策的个人面试知识库。它把零散面经转化为可追溯的原子问答，把重复问题沉淀为持续修订的稳定回答，并围绕真实面试与简历经历形成复习闭环。

## 2. 核心用户问题

求职者的面试信息分散在聊天、论坛、文档和个人回忆中。重复问题需要反复整理，个人回答又会随实践持续变化。通用题库能提供“别人怎么答”，但不能维护“我现在准备怎么答”、这套回答来自哪些经历、在哪些面试中被验证过。

千面解决的不是题目数量问题，而是个人知识的整理、复用、修订和追溯问题。

## 3. 产品价值

1. **从原文到结构**：保留面经来源，同时把内容拆成可编辑的问答单元。
2. **从重复到沉淀**：识别跨面试重复问题，但只建议连接，由用户决定是否形成同步块。
3. **从知识到表达**：同步块保存用户当前认可的稳定回答和复习笔记。
4. **从回答到证据**：问题可关联具体简历经历，回答可以回到真实项目证据。
5. **从整理到复习**：概览页优先推荐同步块，而不是再次展示重复的原子问题。
6. **数据由用户控制**：本地存储、可导出、可删除；AI 使用用户自己的凭据。

## 4. 核心原则

### 4.1 本地优先，不等于完全离线

- 面经、简历、问答、同步块、配置和索引默认保存在用户设备。
- 使用第三方模型时，必要内容会从本机直接发送到用户配置的模型服务。
- 产品不得宣称“AI 请求在本机完成”，除非实际使用本地模型。
- 未配置 AI 或调用失败时，核心的手动导入、编辑、关联、复习和导出仍可使用。

### 4.2 AI 是建议者，不是内容所有者

- AI 可以抽取、分类、匹配、推荐和生成草稿。
- AI 不得静默覆盖用户正文，不得自动合并同步块。
- 所有影响知识库结构或用户正文的 AI 结果必须可审阅、修改、拒绝和撤销。
- 界面优先表达“待审核内容”，而不是突出“AI 能力”。

### 4.3 原文是证据，原子问答是实例，同步块是稳定知识

- 面试记录保存一次面试的上下文和原始内容。
- 原子问答记录该问题在某次或多次面试中的具体问法、回答和来源。
- 同步块保存用户跨场景复用的稳定回答，不替换原始实例。
- 编辑同步块默认不反向改写原子问答；用户可选择把同步块内容引用到具体问答。

### 4.4 先建立可信闭环，再扩大能力边界

一期优先完成文本面经的导入、审核、整理、关联、复习、导出和删除。录屏、视频转写、云同步、多人协作、企业端和自动投递均不进入一期。

## 5. 核心对象

| 对象 | 定义 | 关键关系 |
| --- | --- | --- |
| 面试记录 | 一次具体面试或一篇外部面经 | 包含原文和多个原子问答；可关联简历经历 |
| 原子问答 | 最小可编辑的问题实例 | 必须可追溯到来源；至多引用一个主同步块 |
| 同步块 | 针对一类重复问题维护的稳定回答 | 可连接多个原子问答；保存复习笔记和修订记录 |
| 简历经历 | 实习、项目、工作或教育经历 | 可连接多个原子问答和同步块 |
| 待审核项 | AI 结果或未完成的人工确认任务 | 指向面试、问答、同步候选或简历关联 |
| 复习记录 | 用户对同步块的复习行为 | 用于推荐、去重和后续复习计划 |
| AI 配置 | 模型提供方、端点、模型和凭据引用 | 凭据必须进入系统安全存储 |

## 6. 核心闭环

```text
导入面经原文
  -> 保存来源与本地草稿
  -> AI 拆解或手动拆解
  -> 用户逐条审核
  -> 原子问答入库
  -> 发现重复问题
  -> 用户连接或新建同步块
  -> 编辑稳定回答与复习笔记
  -> 概览推荐复习
  -> 回到原面试和简历经历验证、修订
```

## 7. 信息架构与跨端定位

### PC：主要生产端

- 概览
- 面试记录
- 原子问答
- 同步块
- 简历经历
- 设置
- 全局导入与待审核抽屉

PC 承担批量导入、深度编辑、关系维护、审核和数据管理。

### H5：随身处理端

- 概览
- 面经
- 同步块
- 我的
- 快速导入与待审核底部面板

H5 一期承担浏览、复习、轻量审核和快速导入。原子问答与简历经历可以从关联内容进入，但不要求提供与 PC 同等的批量管理能力。

## 8. 当前原型结论

- PC 当前有效版本：`interview-atlas-pc_uydf/v3`。
- H5 当前有效版本：`interview-atlas-h5_t8k8/v5`。
- H5 v3、v4、v5 的产品代码一致，v4/v5 主要补齐本地运行依赖。
- 现有原型是交互验证稿，数据、进度、推荐结果和保存行为大多是模拟状态，不代表已经确定的数据模型或算法。
- 当前视觉语言适合作为设计基线，但实施时应补齐无障碍、响应式、错误态和键盘操作规范。
- 正式本地应用已在 `src/` 启动实现；原型目录继续作为设计参考，不作为生产代码依赖。

## 9. 一期成功标准

- 新用户无需 AI 也能完成第一条面经的保存和手动拆解。
- 使用 AI 时，用户能理解数据发往何处并在入库前修正结果。
- 任一问答都能追溯到原始面经，任一同步块都能看到关联问题。
- 用户可以完成“导入一篇面经 -> 审核 -> 连接同步块 -> 次日复习”的闭环。
- 全部个人数据可导出、可恢复、可彻底删除。

## 10. 后续工作约束

- 新功能必须说明它服务于核心闭环的哪一段。
- 涉及存储、桌面容器、编辑器、AI 协议或凭据管理的选择必须通过 ADR。
- 原型中的文案和示例数据不能直接作为业务规则。
- 需求变更应同步更新本文件和对应 PRD；实现细节只进入 ADR 或工程文档。
