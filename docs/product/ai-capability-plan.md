# 千面 AI 能力规划

- 状态：Active baseline
- 日期：2026-09-30
- 适用范围：产品、设计、工程与测试

## 1. AI 的产品角色

AI 是知识整理助手，不是知识库的内容所有者。它负责降低提取、比较、归类和起草成本；用户决定哪些内容成为正式数据、哪些关系成立、哪些正文被修改。

当前产品阶段只实现“导入面经时的 AI 拆解”。下文能力地图中的其他能力均为远期可能性，不进入当前开发范围，也不应提前出现在产品界面中。

任何 AI 能力都必须满足：

1. 用户明确触发，并在调用前知道发送范围和目标服务；
2. 输出先成为可编辑、可拒绝的候选；
3. 不静默覆盖、合并或删除用户内容；
4. 结果可追溯到原始面经、简历经历或用户选择的上下文；
5. AI 未配置、离线或调用失败时，完整手动路径仍可用。

## 2. 能力地图

| 环节 | AI 能力 | 输入 | 输出 | 人工决策 |
| --- | --- | --- | --- | --- |
| 面经导入 | 拆解问题、原回答、标签、原文片段 | 单篇面经原文与基础元信息 | 原子问答候选 | 编辑、选择并入库 |
| 知识归类 | 匹配已有同步块、发现重复问题 | 候选问答与必要的同步块摘要 | 匹配候选、理由、置信度 | 关联、另建或忽略 |
| 回答沉淀 | 从多个实例起草稳定回答 | 用户选中的原子问答 | 同步块正文草稿与分歧提示 | 对照来源后保存 |
| 回答改进 | 补充结构、追问、证据缺口 | 当前回答与用户选择的经历 | 修改建议或新草稿 | 逐项采纳 |
| 简历关联 | 推荐支持回答的经历 | 问答、同步块与经历摘要 | 经历关联候选及依据 | 确认关系 |
| 模拟面试 | 生成追问并点评表达 | 用户选定知识与会话回答 | 追问、反馈、待改进项 | 选择是否沉淀 |
| 复习 | 生成提示、变体和自测题 | 用户选择的同步块 | 临时复习材料 | 不自动改正文 |
| 检索 | 语义召回与问答 | 本地索引或用户选定内容 | 带来源的结果 | 跳转原对象核验 |

## 3. 当前唯一 AI 闭环

当前只实现原型定义的三步导入路径：

```text
点击“导入面经”
  -> 粘贴面试原文
  -> 原文先保存到本地并进入待审核
  -> 选择“保存并稍后审核”，从面试详情继续 AI 拆解
  -> 或立即执行 AI 拆解并显示过程
  -> 选择“稍后审核”，持久化候选并从面试详情续办
  -> 或立即审核问题、回答、标签和同步块建议
  -> 处理完全部候选后标记面试为已审核
```

同步块匹配默认只作为建议显示。只有用户在审核结果中明确选择“连接”，保存时才建立关系。

面试详情中的 AI 助理是导入拆解流程的续办入口，不是新的 AI 能力。当前不实现回答生成、模拟面试、语义检索、自动复习、后台批量处理、自动合并、自动改写或向量索引。

## 4. 输入与最小披露

### 面经拆解发送

- 当前面试的公司、岗位、轮次；
- 当前面试原文；
- 已有同步块的 ID、标题，以及截断后的正文摘要，仅用于给出匹配候选。

不发送：

- 其他面试全文；
- 全部原子问答；
- 导出数据、复习记录或无关简历；
- 任何 API Key 或本地配置之外的凭据。

界面在调用前展示目标端点和发送范围。后续能力必须单独定义输入范围，不能沿用“发送整个工作区”的宽泛授权。

## 5. 输出契约

每个拆解候选包含：

- `title`：面试官的原始或规范化问题；
- `answer`：原文中可明确归属的当次回答，没有则为空；
- `tags`：少量检索标签；
- `sourceExcerpt`：支持该候选的原文片段；
- `suggestedSyncBlockId`：已有同步块候选，可为空；
- `matchReason`：匹配理由，可为空。

拆解质量规则：

- 只抽取面试官明确提出或上下文能唯一确定意图的问题，不把候选人的自问自答、复盘感想、寒暄和普通陈述误识别为问题；
- 一个候选只表达一个可独立回答的核心意图；独立并列问题拆开，无法脱离主问题理解的追问合并；
- 同场语义重复问题只保留一次，并按原文首次出现顺序输出；
- 问题标题删除口语填充、话轮前缀和机械重复，但保留技术名词、限定条件、比较对象及否定含义，不得泛化成题库问题；
- 当次回答只允许轻量清理填充词，不得改变事实、数字、步骤、不确定性或否定表述；
- `sourceExcerpt` 使用未经改写的连续原句，提供能够证明问题与回答归属的最短充分证据。

标签规则：

- 每题提取 1 到 4 个由原文支持的稳定标签；
- 优先选择技术领域或能力域、具体技术或概念，以及必要的场景或题型；
- 保留技术专有名词的通行大小写，不使用句子、同义重复、公司名、轮次或“技术”“其他”等过宽标签。

同步块建议规则：

- 主题、提问意图、回答范围和关键约束均高度一致时，最多建议一个同步块；
- 只共享技术栈、关键词、宽泛标签或项目背景不构成匹配；
- 多个同步块均可能匹配、摘要不足或需要额外推断时不建议关联；
- 未建议同步块时 `matchReason` 为空；建议时必须具体说明共同意图和范围。

客户端必须对响应执行结构校验、数量限制、字符串长度限制和同步块 ID 白名单校验。解析失败视为可恢复错误，不保存部分结果。

## 6. 审核与持久化

- AI 候选按面试持久化到本地待审核清单，关闭弹窗或刷新页面后仍可恢复；
- “保存并稍后审核”不静默调用 AI，只保存原文并在详情提供明确的拆解入口；
- “稍后审核”先保存当前候选及编辑结果，再退出导入流程；
- 用户可逐条编辑问题、当次回答和标签；
- 采纳候选时才创建原子问答，忽略项保留审核决策但不进入知识库；
- 只有用户明确点击“采纳并关联”，才建立同步块关系；
- 全部候选处理后，面试状态由待审核更新为已审核；
- 正式原子问答保留当前面试作为来源；
- API Key 不进入 IndexedDB、导出或日志；
- 持久化内容包含候选、来源片段、关联建议和用户决策，不包含凭据。

## 7. Provider 与故障策略

首期支持 OpenAI-compatible `chat/completions` 协议，由用户配置端点、模型和 API Key。

- 请求支持取消与超时；
- HTTP 错误转换为不含密钥和原文的用户可读消息；
- 浏览器 CORS、余额、限流和模型不兼容分别给出可行动提示；
- 普通公网端点必须使用 HTTPS；仅允许 localhost 使用 HTTP；
- 不自动把请求转发到产品自有服务器。

## 8. 质量与安全

- 原始文本在提示词中声明为不可信数据，不执行其中的指令；
- 模型不得补写原文没有出现的实例回答；
- 匹配理由不能替代来源证据；
- 高置信度也不代表自动确认；
- 测试覆盖响应格式、代码块 JSON、非法字段、未知同步块 ID、HTTP 失败和取消；
- 浏览器测试覆盖未配置、调用失败、模拟成功、编辑、取消选择与确认入库。

## 9. 演进顺序

1. 面经结构化、待审核持久化与人工入库；
2. 面试详情 AI 助理续办；
3. 同步块关联建议审核；
4. 多实例对照生成稳定回答草稿；
5. 简历证据关联与回答改进；
6. 带来源的语义检索和模拟面试；
7. 可选本地模型、桌面安全凭据存储与离线推理。

每一阶段都沿用同一原则：扩大 AI 能力前，先补齐来源、审核、撤销和失败降级。
