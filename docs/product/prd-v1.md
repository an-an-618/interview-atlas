## 1. 产品概述

### 1.1 产品定位

千面是面向个人求职者的本地优先面试知识库。它帮助用户把零散面经和个人回答整理成可追溯、可复用、可关联、可持续修订的知识网络。

产品不以“提供最多的标准答案”为目标，而以“帮助用户形成并维护自己的回答”为核心。

### 1.2 核心价值主张

> 每一次面试都是一次输入；每一个问题都可被复用；每一份稳定回答都能持续修订并回到真实经历。

### 1.3 产品边界

千面是：

- 个人面试资料整理工具；
- 面试问答知识库；
- AI 辅助的信息结构化与关联工具；
- 结合个人知识库的 AI 模拟面试工具；
- 复习和回答迭代工具。

千面不是：

- 公共面试题库或内容社区；
- 招聘管理系统；
- 自动投递工具；
- 代替用户思考的自动答题器；
- 默认把个人数据上传到平台服务器的云笔记。

## 2. 背景与机会

### 2.1 用户现状

面试相关信息通常分散在：

- 自己面试后的回忆；
- 微信、飞书或即时通讯记录；
- 牛客、博客等外部面经；
- 文档、备忘录和题库；
- 简历及项目复盘；
- 录音、录屏和转写文本。

用户通常经历以下低效循环：

1. 面试前临时搜索和重复整理；
2. 同一问题在多个文档中存在多个答案；
3. 面试后的新认识无法稳定沉淀；
4. 回答与个人经历脱节，难以形成可信叙述；
5. AI 生成内容缺少来源、确认和长期维护机制。

### 2.2 机会判断

现有题库解决“有哪些问题”，通用笔记解决“把文字记下来”，AI 对话解决“一次生成”。千面的机会是连接三者，建立个人面试知识的生命周期：

```text
采集 -> 结构化 -> 人工确认 -> 去重关联 -> 稳定回答 -> 复习 -> 面试验证 -> 再修订
```

### 2.3 产品假设

一期需要验证：

1. 用户愿意保留原始面经，并在 AI 拆解后做轻量审核。
2. 重复问题对用户有足够价值，值得维护单独的稳定回答。
3. “同步块 + 来源追溯”比普通标签或全文搜索更能减少重复整理。
4. 本地优先和自备 API Key 能提升隐私信任，且不会造成不可接受的配置门槛。
5. 高频同步块推荐能形成持续复习，而不只是一次性整理。

## 3. 用户与场景

### 3.1 一期核心用户

**主要用户：处于集中求职期、有多场面试记录的知识型岗位求职者。**

典型特征：

- 每周有多场面试或持续收集目标岗位面经；
- 已有自己的项目和简历内容；
- 会用文档或笔记整理知识；
- 愿意修订个人答案，而非只背标准答案；
- 对简历、面试内容和 API Key 的隐私敏感；
- PC 是主要整理设备，手机是补录和复习设备。

一期示例数据偏前端工程师，但数据结构和交互不得绑定技术岗位。

### 3.2 次要用户

- 刚开始求职、数据量较少但希望建立结构化习惯的用户；
- 产品、设计、运营、咨询等需要行为面和项目复盘的岗位用户；
- 不使用 AI、完全依靠手动整理的隐私敏感用户。

### 3.3 暂不服务

- 企业招聘方和面试官；
- 多人共享题库或培训机构；
- 需要实时面试辅助或作弊能力的用户；
- 需要自动投递、职位跟踪等完整求职 CRM 的用户。

### 3.4 高频任务

| 场景 | 用户目标 | 频率 | 首选端 |
| --- | --- | --- | --- |
| 面试后整理 | 快速保存原文并拆成问题 | 每场面试后 | PC/H5 |
| 外部面经导入 | 把帖子或聊天内容纳入个人库 | 高频 | PC |
| 审核 AI 结果 | 修正问题、答案和关联 | 每次导入后 | PC，H5 轻量支持 |
| 重复问题沉淀 | 建立或更新稳定回答 | 每周多次 | PC |
| 面试前复习 | 查看今天最值得复习的内容 | 每日 | H5/PC |
| 回溯证据 | 从回答查看原面试和简历经历 | 按需 | PC |
| 数据备份 | 导出、迁移或恢复个人库 | 低频但关键 | PC |

## 4. 产品目标与非目标

### 4.1 一期目标

1. 建立文本面经从导入到入库的可信闭环。
2. 建立面试记录、原子问答、同步块和简历经历之间的可追溯关系。
3. 允许用户持续维护自己的稳定回答，而不丢失各次面试实例。
4. 提供简单、可解释、可控制的复习推荐。
5. 提供完整的数据导出、恢复和删除能力。
6. 在无 AI、AI 失败或离线状态下保留核心手动能力。

### 4.2 一期非目标

- 录屏、视频管理、实时转写；
- 云同步和多人协作；
- 公共内容社区或题库市场；
- 招聘企业端；
- 自动投递和职位流程管理；
- 自动替用户生成并覆盖最终答案；
- 复杂记忆算法、考试模式和积分体系；
- 针对某一技术岗位的专用知识图谱。

## 5. 产品原则

### 5.1 本地优先

- 默认数据只保存在用户设备。
- 用户明确触发 AI 后，最小必要内容才发往用户配置的模型服务。
- 所有数据流向必须在设置和首次调用前说明。

### 5.2 人工最终决策

- AI 结果默认进入草稿或待审核态。
- AI 不得静默创建结构关系、合并内容或覆盖用户正文。
- 高风险批量操作必须有预览、确认和撤销。

### 5.3 原始上下文不可丢

- 导入后必须先保存原文草稿，再执行 AI。
- 问答与同步块必须能回溯来源。
- 用户修订后的稳定回答与原始回答分层保存。

### 5.4 复习面向稳定知识

- 概览优先推荐同步块，而不是重复展示多个相似原子问答。
- 频次是解释信号，不是唯一推荐依据。
- 用户可以隐藏、置顶、稍后再看或调整复习状态。

### 5.5 核心路径不依赖 AI

- 用户可以手动创建面试记录、问题、答案和同步块。
- AI 不可用时，系统提供可理解的降级路径，而不是阻断任务。

## 6. 核心概念与关系

### 6.1 面试记录 Interview

表示一次真实面试或一篇外部面经。

必需字段：

- 标题；
- 日期或“日期未知”；
- 来源类型；
- 原始文本；
- 状态；
- 创建时间、更新时间。

可选字段：

- 公司、岗位、轮次；
- 时长、面试官；
- 来源链接或备注；
- 关联简历经历；
- 标签。

关系：

- 一条面试记录包含零到多个原子问答；
- 可关联零到多个简历经历；
- 删除面试记录时不得默认删除被其他记录引用的问答或同步块。

### 6.2 原子问答 Atomic Q&A

表示一个可独立编辑、复用和追溯的问题实例。

必需字段：

- 标准化问题标题；
- 审核状态；
- 创建时间、更新时间。

可选字段：

- 当次回答；
- 补充材料；
- 标签；
- 用户自评；
- 主同步块引用；
- 在原文中的位置。

一期定义：

- 原子问答可以独立创建；独立内容明确标记“独立创建”，并可稍后关联面试记录。
- 审核后的问题标题即原子问答的唯一问法，不重复保存“原始问法”。
- 一个原子问答可出现在多个面试记录中，来源上下文由关联的面试原文保留。
- 一个原子问答至多引用一个“主同步块”，避免答案归属不清。
- 同类问题不强制合并为同一原子对象；可以通过同步块聚合。

### 6.3 同步块 Synchronized Block

表示用户针对一类重复问题维护的稳定回答。

必需字段：

- 标题；
- 稳定回答正文；
- 创建时间、更新时间。

可选字段：

- 复习笔记；
- 标签；
- 置顶、隐藏状态；
- 关联原子问答；
- 修订摘要。

一期同步语义：

- 同步块保存共享正文和引用关系。
- 原子问答保留当次回答，不被同步块自动覆盖。
- 在面试详情中展示同步块摘要和跳转入口。
- 用户可以显式执行“用同步块内容更新本题回答”或“把本题改动更新到同步块”；操作前展示差异并确认。
- 解除连接不删除双方内容。

### 6.4 简历经历 Resume Experience

表示用户简历中的实习、工作、项目、教育或其他经历。

字段：

- 类型、标题、组织；
- 起止时间；
- 经历要点；
- 原始导入来源；
- 关联问题和同步块；
- 创建时间、更新时间。

### 6.5 待审核项 Review Item

待审核项是任务，不是独立知识内容。类型包括：

- AI 提取出的问答；
- 重复问题或同步块连接候选；
- AI 回答草稿或补充建议；
- 简历经历关联候选；
- 导入信息缺失提醒。

每个待审核项必须包含：

- 来源对象；
- 建议类型；
- 建议内容；
- 生成时间；
- 当前状态；
- 可执行动作。

状态为：`待处理`、`已采纳`、`已修改后采纳`、`已忽略`、`处理失败`。

### 6.6 复习记录 Review Event

记录用户对同步块的复习行为：

- 复习时间；
- 结果：记得、模糊、不会、跳过；
- 下次复习时间；
- 可选备注。

“同步次数”与“问题出现次数”必须分开：

- **出现次数**：问题在来源记录中出现的次数；
- **关联数**：同步块连接的原子问答数量；
- **复习次数**：用户实际完成复习的次数。

原型中三者存在混用，一期实现必须在数据和文案上消除歧义。

### 6.7 模拟面试 Mock Interview

表示一次 AI 面试官与用户的完整模拟会话。

必需字段：

- 公司、岗位；
- 面试官 Prompt；
- 目标问题数；
- 对话消息与状态；
- 开始时间、更新时间。

可选字段：

- 目标轮次、岗位 JD、补充信息；
- 结束时间、结束方式和原因；
- 反馈报告；
- 生成的面试记录与原子问答引用。

一期定义：

- 公司、岗位、JD、补充信息和知识库上下文固定注入 System Prompt，用户可编辑其余面试策略；
- 面试官每轮只推进面试，不在过程中评价当前回答；
- AI 满足结束条件时可主动结束，用户也可随时结束；
- 每次用户回答先保存在本地，再请求 AI；
- 结束时先保存带“模拟面”标识的面试记录，再生成反馈和原子问答；
- 原子问答不增加“模拟面”标识，不自动关联同步块；
- 报告生成失败不删除逐字稿，允许稍后重试。

### 6.8 对象关系

```text
面试记录 1 --- N 来源关系 N --- 1 原子问答
原子问答 N --- 0..1 同步块
简历经历 N --- N 原子问答
简历经历 N --- N 同步块
同步块 1 --- N 复习记录
待审核项 N --- 1 来源对象
模拟面试 1 --- 0..1 面试记录
模拟面试 1 --- N 原子问答
```

## 8. 核心用户流程

### 8.1 首次使用

1. 用户看到本地优先说明。
2. 用户选择“先手动使用”或“配置 AI”。
3. 若配置 AI，选择兼容协议、服务地址、模型并输入 API Key。
4. 系统只验证连接，不上传知识库历史内容。
5. 用户进入空状态概览，可导入面经、创建面试或导入简历。

验收要求：

- 不配置 AI 也能进入产品。
- 首次说明明确区分本地存储与第三方 AI 传输。
- 示例数据不得混入真实用户库。

### 8.2 导入面经

1. 用户点击全局“导入面经”。
2. 粘贴原文，选择来源类型并补充元信息。
3. 系统立即将原文保存为本地草稿。
4. 用户选择 AI 拆解或手动拆解。
5. AI 拆解时显示阶段、取消入口和发送范围。
6. 结果页逐条展示候选问题、答案、标签和同步候选。
7. 用户可编辑、取消勾选、改为新问题或连接已有同步块。
8. 用户保存为待审核草稿，或确认后入库。

异常处理：

- 空文本：禁止提交并提示。
- 文本过长：显示可支持上限，允许分段或只手动保存。
- 网络失败：原文草稿不丢失，可重试或转手动。
- Key 无效或余额不足：说明模型服务返回的原因，不暴露密钥。
- 解析出零个问题：保留原文，允许手动新建问题。
- 页面关闭或系统休眠：恢复未完成草稿和审核进度。

### 8.3 审核 AI 结果

1. 用户从概览或面试详情进入待审核项。
2. 系统展示来源原文片段、AI 结果和建议动作。
3. 用户可以采纳、编辑后采纳、忽略或稍后处理。
4. 结构变化必须显示影响范围。
5. 完成后更新面试记录审核进度。

规则：

- “全部采纳”仅在每条结果均有明确默认去向时可用。
- 低可信结果不使用隐藏阈值直接丢弃，应标为“需要重点确认”。
- 原型中的置信度百分比不作为用户必须理解的核心指标；优先解释“为什么建议”。
- 忽略结果可在 30 天内从操作历史恢复。

### 8.4 创建和维护同步块

入口：

- 同步块列表“新建”；
- 原子问答“连接同步块”；
- 待审核的重复问题候选。

流程：

1. 输入标题和稳定回答。
2. 可选填写复习笔记。
3. 选择关联原子问答。
4. 若问题已有主同步块，明确提示并要求选择“移动连接”或“取消”。
5. 保存后建立引用关系。

编辑规则：

- 保存同步块时不自动覆盖原子问答。
- 用户可查看正文修订历史并恢复最近版本。
- 删除同步块前展示关联数量；删除后原子问答保留并变为未连接。
- 合并两个同步块时必须预览标题、正文、笔记和关联关系的处理结果。

### 8.5 每日复习

1. 概览展示最多 3 个待复习同步块。
2. 用户进入同步块查看稳定回答、笔记和来源。
3. 用户选择“记得”“模糊”“不会”或“跳过”。
4. 系统记录结果并计算下次复习时间。
5. 用户可换一批、置顶或隐藏。

一期推荐规则：

```text
候选 = 未隐藏且未归档的同步块
优先级 = 到期状态 > 用户置顶 > 近期出现频次 > 距上次复习时间
同日去重 = 当日完成或跳过的同步块不再次推荐
跨日去重 = 默认避免连续两日重复，逾期或用户置顶除外
不足 3 条 = 展示实际数量，不制造重复
```

冷启动：

- 无同步块：引导导入面经或手动创建；
- 有同步块但无复习记录：按出现频次和更新时间推荐；
- 用户可以关闭每日推荐。

### 8.6 简历经历关联

1. 用户手动创建或导入简历经历。
2. 用户编辑经历要点。
3. 用户手动关联原子问答或同步块。
4. AI 可提出候选，但需用户确认。
5. 从面试、问答、同步块和简历经历均可双向跳转。

一期不要求自动生成整份简历，不要求将知识库内容回写为可投递简历。

### 8.7 导出、备份、恢复与删除

导出格式：

- Markdown：适合阅读和长期保存；
- JSON：完整保留对象、关系、状态和版本信息；
- 可选附件目录：一期若没有附件则不生成。

备份要求：

- 支持导出全量备份；
- 文件包含格式版本、导出时间和应用版本；
- 恢复前预检格式、容量和冲突；
- 支持“导入为新库”与“合并到当前库”；
- 合并前必须展示新增、重复和冲突数量。

删除要求：

- 支持删除单个对象；
- 支持清空全部本地数据；
- 清空前要求二次确认和明确不可恢复提示；
- 当前浏览器与桌面 WebView 版本删除 API Key 时，同时移除会话存储中的凭据；
- 后续若引入系统安全存储，删除操作必须同时移除其中的凭据；
- 产品需说明普通删除与安全擦除在不同文件系统上的实际边界。

### 8.8 模拟面试

1. 用户输入公司、岗位、可选轮次、岗位 JD 和补充信息。
2. 系统展示将发送的知识库类别、数量上限和目标模型端点。
3. 用户可展开并编辑面试官 Prompt 的策略部分。
4. 用户开始面试，AI 结合相关历史面试、简历经历、原子问答和同步块提出第一问。
5. 用户每次提交回答后，系统先保存回答，再请求下一轮。
6. AI 根据目标问题数、信息充分度和用户状态决定继续追问或自然结束；用户可主动结束。
7. 系统立即保存逐字稿为一条带“模拟面”标识的面试记录。
8. 独立评估 Prompt 生成反馈报告，并自动拆分原子问答。
9. 用户可从报告进入面试记录，并按普通知识库逻辑编辑问答或关联同步块。

异常处理：

- 模型请求失败：保留已保存的全部消息，允许重试当前轮；
- 报告请求失败：保留已结束面试和逐字稿，允许重新生成报告；
- 页面关闭或切换：保留进行中的会话，可从历史模拟继续；
- AI 提前结束：必须返回自然收尾和内部结束原因，报告生成逻辑不变；
- 结构化输出无效：不写入部分报告或问答，显示可理解错误。

## 13. AI 产品规则

### 13.1 支持任务

- 面经元信息抽取；
- 问题、答案和材料拆解；
- 标签建议；
- 重复问题和同步块候选；
- 回答缺口提示；
- 简历经历关联候选。

### 13.2 禁止行为

- 未经确认覆盖用户正文；
- 未经确认合并、删除或移动知识对象；
- 隐瞒发送给第三方模型的内容；
- 把模型输出伪装成用户原始记录；
- 在日志中记录完整面经、简历或密钥；
- 失败后重复调用并产生不可控费用。

### 13.3 可解释性

同步候选至少展示：

- 被比较的对象；
- 相似的关键内容；
- 建议连接到哪个同步块；
- 连接后会改变什么；
- 用户可选的替代动作。

### 13.4 降级

| 故障 | 产品行为 |
| --- | --- |
| 未配置 Key | 保留原文并提供手动拆解 |
| Key 无效 | 停止调用，保留草稿，进入设置修复 |
| 网络中断 | 保留进度，允许重试 |
| 模型限流 | 展示服务返回的重试建议，不自动无限重试 |
| 输出格式错误 | 保存原始模型响应的脱敏诊断，允许重新解析 |
| 部分成功 | 展示已完成结果，失败部分可单独重试 |
| 用户取消 | 停止后续请求，不删除本地草稿 |

## 14. 隐私与安全

### 14.1 数据分级

高敏感：

- API Key；
- 简历原文；
- 面试录音、录屏和转写；
- 面试官身份信息；
- 用户私人评价。

敏感：

- 面经正文；
- 问答和同步块；
- 公司、岗位和求职时间线；
- 模型提示词和输出。

一般：

- 无个人内容的界面偏好；
- 应用版本和本地格式版本。

### 14.2 要求

- 凭据使用操作系统安全存储；
- 本地数据库不保存明文 Key；
- 日志默认不记录正文；
- 崩溃报告默认不附带用户内容；
- 网络请求仅发往用户选择的 endpoint；
- 自定义 endpoint 必须明确风险；
- 导出文件默认不包含 API Key；
- 删除和恢复操作有审计型本地事件记录，但不保存被删除正文；
- 示例和测试数据必须为虚构数据。

### 14.3 隐私文案

禁止使用绝对化或不准确表达：

- 不应写：“AI 请求都在本机完成”。
- 可以写：“数据默认保存在本机；使用 AI 时，所选内容会从本机直接发送到你配置的模型服务，不经过千面服务器。”

若未来提供本地模型，可单独标记“完全离线处理”。

## 15. 非功能需求

### 15.1 性能

- 冷启动至可操作：目标小于 2 秒，以约 1,000 条面试、20,000 个问答为基准；
- 本地搜索首屏结果：目标小于 200 毫秒；
- 编辑自动保存：用户停止输入后 1 秒内持久化；
- 大文本导入不得阻塞主界面；
- AI 任务可以取消，且不阻止浏览已有内容。

### 15.2 可靠性

- 所有写操作应具备事务边界；
- 应用异常退出后恢复最近草稿；
- 导入失败不得留下半关联对象；
- 数据模型升级前自动备份；
- 恢复失败时保持原库不变。

### 15.3 可访问性

- 核心操作支持键盘完成；
- 焦点状态可见；
- 图标按钮有可访问名称和提示；
- 正文、次要文字、状态色满足 WCAG AA 对比度目标；
- 状态不能只依赖颜色；
- H5 触控目标不小于 44×44 CSS 像素；
- 支持系统减少动效设置。

### 15.4 兼容性

当前兼容性基线：

- 当前和前一主版本的 Chrome/Edge；
- 桌面版支持 Apple Silicon macOS 13 及以上与 x64 Windows 10/11；
- Linux 与 Intel/Universal macOS 安装包待独立验证后开放；
- H5 覆盖 iOS Safari 与 Android Chrome 的当前主版本。

### 15.5 国际化

一期界面为简体中文，数据允许任意语言。对象字段、导出格式和搜索不得假设内容只有中文。

### 16.1 已形成的设计语言

- 低饱和暖纸色背景；
- 深墨色正文；
- 铁锈橙作为主要强调色；
- 苔绿色用于已完成或安全状态；
- 衬线字体用于标题和知识内容；
- 无衬线字体用于控制、元信息和长文本；
- 细边框、低阴影、紧凑的信息密度。

该语言强调“私人笔记、长期修订和可信沉淀”，与产品定位一致。

### 16.2 交互原则

- 编辑、删除、连接、同步等动作要区分；
- 不用“已同步 ×N”同时表达出现频次与复习次数；
- AI 入口从属于具体工作流，不独立占据一级导航；
- PC 的三栏面试工作区用于同时查看目录、正文和建议；
- H5 用顶部返回、底部导航和底部面板降低层级切换成本；
- 保存和本地状态使用即时反馈；
- 高风险动作必须确认，普通编辑使用自动保存与撤销。

### 16.3 原型需修正项

- PC 与 H5 的视觉说明均直接称为“Claude Design System”，正式产品需形成自己的设计命名与品牌规范。
- 原型仍依赖 Google Fonts；若要求真正离线，应使用系统字体或随应用合法打包字体。
- H5 固定 9:19.5 画布适合演示，不是生产响应式方案。
- 当前部分按钮没有真实行为，包括排序、编辑、导出、全部审核等。
- PC 的编辑器目前是静态富文本展示，不代表已选择正式编辑器。
- 首页日期、示例用户、数量和进度为硬编码演示值。

## 17. 数据分析与成功指标

本地优先默认不上传行为数据。指标优先在设备本地计算并展示；若未来提供匿名遥测，必须单独征得同意。

### 17.1 北极星指标

**每周完成复习且发生有效修订的同步块数量。**

它同时反映内容沉淀、复习使用和答案迭代，而不是单纯导入量。

### 17.2 核心指标

- 首次导入完成率；
- AI 拆解后的审核完成率；
- 单条面经从导入到审核完成的中位时长；
- 原子问答连接同步块的比例；
- 每周复习同步块数量；
- 复习后发生正文或笔记修订的比例；
- 导出成功率与恢复成功率；
- AI 失败后的手动流程继续率。

### 17.3 质量指标

- AI 抽取结果的修改后采纳率；
- 同步候选的采纳率；
- 误合并后的撤销率；
- 孤立关系或数据完整性错误数；
- 未保存内容丢失事件数。

### 17.4 一期验证建议

在正式开发前用 5 至 8 名目标用户完成可用性测试：

1. 导入一篇真实但脱敏的面经；
2. 修正 AI 拆解；
3. 连接一个已有同步块；
4. 创建一个新同步块；
5. 从同步块回到原始面试；
6. 关联一个简历经历；
7. 完成一次复习；
8. 导出并恢复测试库。

记录完成率、耗时、误解点和放弃原因。

## 19. 验收场景

### AC-01 无 AI 完成闭环

给定用户未配置 API Key，当用户粘贴面经并选择手动整理时，可以保存原文、创建问答、创建同步块并在概览中复习。

### AC-02 AI 失败不丢数据

给定 AI 请求因网络失败，当用户返回面试记录时，原文草稿、元信息和已完成的手动修改仍然存在，并可重试或转手动。

### AC-03 同步不覆盖实例

给定一个同步块连接两个原子问答，当用户修改同步块正文时，两个原子问答的当次回答保持不变；系统提供显式更新入口和差异预览。

### AC-04 全链路追溯

给定一个同步块，用户可以查看其关联问答、对应面试和关联简历经历，并能沿返回路径回到原位置。

### AC-05 推荐可解释

给定三个今日推荐，用户可以看见每项被推荐的原因；完成、跳过或换一批后，当日不会无解释重复出现。

### AC-06 数据可迁移

给定一个包含关系和复习记录的知识库，用户导出 JSON 后清空本地数据，再恢复该文件，所有对象、关系和关键状态保持一致。

### AC-07 删除影响明确

给定一条连接同步块和简历经历的问答，删除前系统展示影响；删除后其他对象仍存在且不包含失效引用。

### AC-08 跨端任务一致

给定同一份本地测试数据，PC 和 H5 对面试状态、待审核数量、复习结果和同步块内容的含义一致，不出现同一字段跨端不同解释。

## 21. 风险与应对

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 同步块概念难理解 | 用户无法区分实例回答和稳定回答 | 首次连接时用真实前后对比解释，文案统一 |
| 审核成本过高 | AI 导入后用户放弃 | 支持保存草稿、逐条快捷处理、突出高风险项 |
| AI 匹配错误 | 错误合并污染知识库 | 默认只建议，显示理由，支持撤销和历史 |
| 自备 Key 门槛高 | 新用户无法体验 AI | 手动模式完整可用，提供连接检测和清晰错误 |
| 本地数据丢失 | 用户失去核心资产 | 自动草稿、导出提醒、可选自动备份、升级前备份 |
| “本地优先”被误解 | 隐私信任受损 | 明确第三方模型数据流，不使用绝对化文案 |
| 过度依赖出现频次 | 推荐价值低 | 加入到期、置顶、复习结果和隐藏状态 |
| PC/H5 功能割裂 | 任务无法跨端继续 | 统一对象语义和状态，明确端侧职责 |

## 22. 待决策问题

以下问题不能由当前原型直接决定：

1. 一期实际运行形态及支持的操作系统；
2. H5 是否需要跨设备数据同步，若需要，如何满足本地优先；
3. 原子问答是跨来源唯一对象，还是每次出现均为独立实例；
4. 同步块正文更新的显式双向同步交互；
5. 复习算法采用固定间隔还是简化间隔重复；
6. 是否在一期提供内容版本历史和多级撤销；
7. 支持的首发 AI 协议和提供方；
8. 自定义 endpoint 的证书、代理和数据安全提示；
9. 本地数据库是否默认加密及密钥恢复方式；
10. H5 是响应式页面、PWA 还是桌面应用的移动预览模式；
11. Markdown 导出的稳定目录与文件命名规范；
12. 用户是否需要多个独立知识库或求职周期。

建议在技术选型前，优先通过用户测试确认第 3、4、5、10 项。

## 25. 评审建议

第一次产品评审聚焦以下四个问题，不讨论具体框架：

1. 用户是否理解“原子问答”和“同步块”的区别？
2. 同步块应如何与实例回答发生显式内容更新？
3. 一期复习是否需要结果反馈与简单间隔计划？
4. PC 主生产、H5 主消费的端侧分工是否成立？

上述问题确认后，再进入数据模型、运行形态、编辑器与 AI Provider 的 ADR 评审。
